# DA/DT编码与Pn/Fn算法

数据单元标识固定4字节，线上顺序：

```text
DA1 DA2 DT1 DT2
```

DA1、DT1都是位图，可能同时置多个bit；解析器必须输出全部Pn/Fn，不能只取最低置位。

来源：S2009-PDF 4.3.4.4、图7～图9；REV13-DOC 4.3.4.4、图8～图10；EXT-V1.6 3.1～3.4。

## DA：信息点

标准普通点算法：

```text
for bit in 0..7:
    if DA1 & (1 << bit):
        Pn = (DA2 - 1) * 8 + bit + 1
```

该公式要求 `DA2` 为1～255，可表示P1～P2040。

特殊值：

| DA1 DA2 | 含义 |
|---|---|
| `00 00` | 终端信息点P0 |
| `FF 00` | 所有有效测量点，不含P0 |

文档没有定义 `DA2=00` 时除 `00 00`、`FF 00` 以外的组合，也没有定义 `DA1=00, DA2!=00`。遇到这些值应标“当前资料未定义/疑似非法”，不得套公式产生负数或空点。

Pn的业务语义取决于Fn，可能是测量点号、总加组号、控制轮次、直流模拟量端口号或任务号。

## DT：信息类

标准算法：

```text
for bit in 0..7:
    if DT1 & (1 << bit):
        Fn = DT2 * 8 + bit + 1
```

标准2009/修订资料定义DT2组号0～30，即F1～F248；DT2=31～255在标准profile中未定义。

示例：

| DT1 DT2 | 结果 |
|---|---|
| `01 00` | F1 |
| `80 00` | F8 |
| `01 01` | F9 |
| `04 02` | F19 |
| `03 00` | 同时选择F1、F2 |

`DT1=00`在标准Fn选择中不产生Fn；AFN=08的级联主动上报请求明确使用 `DA=0、DT=0`，属于有文档依据的特例。

## 厂站2.0扩展Fn

`station-2.0-v1.6` profile允许DT2超过30，仍沿用相同公式：

| Fn | DT1 DT2 | 业务 |
|---:|---|---|
| 792 | `80 62` | 查询模块信息 |
| 794 | `02 63` | 综合信息查询 |
| 796 | `08 63` | 扩展参数配置 |
| 816 | `80 65` | 采集任务配置 |
| 817 | `01 66` | 电表档案配置 |
| 818 | `02 66` | 通讯端口参数配置 |
| 819 | `04 66` | 主站连接参数配置 |
| 820 | `08 66` | 恢复采集任务默认配置；资料未给数据体 |
| 821 | `10 66` | 102协议信息体配置 |

AFN=FE的F4/F5仍使用标准DT算法：F4=`08 00`，F5=`10 00`。

## 多Pn、多Fn的数据顺序

标准规定数据组织顺序为先Pn从小到大，再Fn从小到大：处理完一个Pi的全部Fn后，再处理下一个Pi+1。特殊选择器 `FF 00` 的实际有效测量点集合需要终端档案上下文。

解析器必须先展开DA、DT，再按上述笛卡尔顺序匹配业务体；业务体长度由对应AFN/Fn schema决定。
