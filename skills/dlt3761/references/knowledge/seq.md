# 帧序列域 SEQ

```text
bit: D7   D6   D5   D4   D3..D0
     TpV  FIR  FIN  CON  PSEQ/RSEQ
```

来源：S2009-PDF 4.3.4.3、图5、表6；REV13-DOC 4.3.4.3。

| 位 | 含义 |
|---|---|
| TpV | 1=AUX末尾带6字节时间标签Tp；0=无Tp |
| FIR | 1=应用报文第一帧 |
| FIN | 1=应用报文最后一帧 |
| CON | 1=接收方需要对本帧确认；0=不要求 |
| PSEQ/RSEQ | 低4位序号，启动帧解释为PSEQ，响应帧解释为RSEQ |

## FIR/FIN组合

| FIR | FIN | 含义 |
|---:|---:|---|
| 0 | 0 | 多帧中间帧 |
| 0 | 1 | 多帧结束帧 |
| 1 | 0 | 多帧首帧，仍有后续 |
| 1 | 1 | 单帧 |

每个分帧仍带自己的数据单元标识，并可独立进行帧结构校验。应用层重组必须按同一通信服务、方向、地址、AFN和序号关系进行，不能仅凭FIR/FIN拼接相邻TCP包。

## 序号规则

- PSEQ取启动帧计数器PFC的低4位。
- PFC为每对启动站/从动站独立维护的8位计数器；每发一个新启动帧加1，0～255循环；重发不加。
- 第一响应帧 `RSEQ=PSEQ`，后续响应帧RSEQ按0～15循环加1。
- 超时重发的PSEQ保持不变，最多重发3次（具体次数可配置）。
- TpV=0时，重复PSEQ通常表示对方未收到响应，从动站应重发响应而不重复处理；启动站收到重复RSEQ时不处理第二份。
- TpV=1时还必须结合Tp的PFC和时效判断，不能只按低4位去重。

AFN=00确认/否认必须是单帧：FIR=1、FIN=1、CON=0。
