# 解帧示例

以下报文是依据标准规则构造的“终端登录”示例，用于验证字段算法，不是四份文档中的原始抓包：

```text
68 32 00 32 00 68 C9 34 12 2E 16 00 02 71 00 00 01 00 C7 16
```

## 逐字节解析

```text
68                第一个启动字符

32 00             第一份长度
32 00             第二份长度，副本一致
                  Lraw = 0x0032 = 50
                  protocol_id = 50 & 3 = 2（本376.1协议）
                  L1 = 50 >> 2 = 12字节
                  整帧长度 = 12 + 8 = 20字节

68                第二个启动字符

C9                控制域C = 1100 1001b
                  DIR=1：终端 -> 主站
                  PRM=1：终端是本次链路服务启动站
                  ACD=0：无重要事件等待访问
                  D4=0：上行保留位
                  FUNC=9：链路测试，请求/响应

34 12             A1行政区划码 = 1234（BCD低字节在前）
2E 16             A2终端地址 = 0x162E = 5678
00                A3：group=0，MSA=0

02                AFN=02，链路接口检测

71                SEQ = 0111 0001b
                  TpV=0，无Tp
                  FIR=1，FIN=1：单帧
                  CON=1：请求确认
                  PSEQ=1

00 00             DA=P0
01 00             DT=F1
                  F1=登录，无业务数据体

C7                CS
                  sum(C9..最后一个00) & FF = C7，正确

16                结束字符
```

## 结论

```text
帧方向：终端 -> 主站
链路服务：终端启动的链路测试
AFN：02
Fn：F1
业务含义：登录
校验：正确
完整性：完整单帧
profile：standard-2009 与 revision-2012-2013公共定义
```

## DA多点示例

```text
DA = 05 02
```

DA2=2表示P9～P16组；DA1=`00000101b`置bit0和bit2：

```text
Pn(bit0) = (2-1)*8 + 0 + 1 = P9
Pn(bit2) = (2-1)*8 + 2 + 1 = P11
```

结果是P9、P11，不是十六进制点号`0x0205`。

## F819的DT示例

```text
Fn = 819
group = floor((819-1)/8) = 102 = 0x66
bit = (819-1)%8 = 2
DT1 = 1<<2 = 0x04
DT = 04 66
```

标准profile会把DT2=0x66判为未定义；`station-2.0-v1.6`才解释为主站连接参数配置。
